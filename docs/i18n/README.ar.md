## نظرة عامة

**AllocSight** هو محرك سطر أوامر عالي التوازي لتحليل تخصيص مجموعات الأقراص (Disk Clusters) واستعادة المساحة تلقائياً على نظام Windows، دون أي تبعيات خارجية. كُتب بلغة C++17 الأصلية مباشرة فوق واجهات برمجة تطبيقات إدارة الملفات في Win32، وصُمم لمطوري البرمجيات ومسؤولي الأنظمة ووكلاء الذكاء الاصطناعي المستقلين الذين يحتاجون إلى قياسات دقيقة وسريعة للتخزين في أجزاء من الثانية دون عبء العرض الرسومي.

على عكس الأدوات التقليدية التي تعرض الحجم المنطقي للملفات فقط (`nFileSizeLow` / `nFileSizeHigh`)، يقوم AllocSight بحساب **التخصيص الفعلي لمجموعات NTFS الفيزيائية**، مع معالجة دقيقة لمحاذاة حجم المجموعة، وضغط NTFS الشفاف (LZNT1/XPRESS)، والملفات المتناثرة (Sparse Files)، وملفات الاستدعاء السحابية، وتدفقات البيانات البديلة (ADS).

## القدرات التقنية الأساسية

1. **فهرسة المجلدات متعددة الخيوط على مستوى النواة**
   يعتمد على مجموعة خيوط عمل (من 8 إلى 16 خيطاً) فوق طابور مهام منخفض التنازع (`ParallelScanner`). يستدعي كل خيط الدالة `FindFirstFileExW` مع العلم `FindExInfoBasic` (لتجاوز البحث عن الأسماء القصيرة 8.3) والعلم `FIND_FIRST_EX_LARGE_FETCH` (لتمكين قراءة مخازن المجلدات الكبيرة من النواة).
2. **حساب دقيق للمجموعات الفيزيائية في نظام NTFS**
   - محاذاة تخصيص كل ملف مع حجم المجموعة الفعلي للقسم المستهدف (`GetDiskFreeSpaceW`).
   - استعلام الحجم الفيزيائي الفعلي للملفات المضغوطة أو المتناثرة عبر `GetCompressedFileSizeW` عند وجود `FILE_ATTRIBUTE_COMPRESSED` أو `FILE_ATTRIBUTE_SPARSE_FILE`.
   - التعرف على الملفات السحابية غير المحملة محلياً (`FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`، `FILE_ATTRIBUTE_RECALL_ON_OPEN`، `FILE_ATTRIBUTE_OFFLINE`) باعتبارها تستهلك `0` بايت محلي.
   - فحص تدفقات البيانات البديلة لنظام NTFS (`:$DATA`) اختيارياً عبر واجهات `FindFirstStreamW` / `FindNextStreamW` الموثقة (`--ads`).
3. **منع الحلقات اللانهائية لنقاط إعادة التحليل (Reparse Points)**
   يفحص وسم `WIN32_FIND_DATAW::dwReserved0` باستخدام وحدات الماكرو القياسية في `<winnt.h>` (`IsReparseTagNameSurrogate`، `IO_REPARSE_TAG_SYMLINK`، `IO_REPARSE_TAG_MOUNT_POINT`) لمنع التكرار اللانهائي الناتج عن الروابط الرمزية ونقاط الوصل.
4. **محرك استدلالي لاستعادة المساحة**
   يصنف المساحة القابلة للاستعادة إلى مستويين واضحين:
   - **`[SAFE]`**: ملفات التخزين المؤقت الحتمية لمديري الحزم (`uv`، `pip`، `conda/pkgs`، `npm/_cacache`، `pnpm-cache`)، وذاكرة التخزين المؤقت للمظللات (`DXCache`، `ShaderCache`)، وملفات تفريغ الأعطال.
   - **`[REVIEW]`**: الأرشيفات المضغوطة التي تم فك ضغطها بالفعل في مجلد مجاور يحمل نفس الاسم الأساسي، ومجلدات النسخ المكررة، ومخرجات البناء القابلة لإعادة الإنشاء (`target`، `node_modules`، `.venv`)، والملفات الضخمة غير المعدلة منذ أكثر من 180 يوماً.
5. **تقارير Markdown و JSON قابلة للنقر المباشر**
   ينشئ جداول Markdown منظمة (`allocsight report`) ومخرجات JSON قياسية (`-j`) تحتوي على روابط `file:///` مرمزة وفق معيار RFC 8089 لفتح أي مجلد أو ملف بنقرة واحدة.

## بنية النظام

![AllocSight System Architecture](assets/architecture.png)

ينظم الكود المصدري كخط أنابيب معياري بلغة C++17 داخل المجلد [`src/`](../../src/):

| الوحدة | المسؤولية الأساسية |
| :--- | :--- |
| [`src/alloc_types.hpp`](../../src/alloc_types.hpp) | تمثيل شجرة `FsNode`، حساب محاذاة المجموعات `VolumeMetrics`، تفعيل صلاحية `SeBackupPrivilege`، التحويل بين UTF-8 و UTF-16، وترميز روابط `file:///`. |
| [`src/alloc_scanner.hpp`](../../src/alloc_scanner.hpp) | طابور العمل متعدد الخيوط `ParallelScanner`، الفهرسة السريعة عبر `FindFirstFileExW`، الحماية من حلقات الروابط الرمزية، وفاحص التدفقات `NtfsStreamInspector`. |
| [`src/alloc_filter.hpp`](../../src/alloc_filter.hpp) | محرك التصفية `QueryFilter` بخوارزمية المؤشرين غير العودية (`wildcardMatch`)، وتقييم قوائم الشروط `MetricPredicate` و `AttributePredicate`. |
| [`src/alloc_views.hpp`](../../src/alloc_views.hpp) | محركات العرض `ReportEngine` (`drives`، `tree`، `top`، `categories`، `analyze`، `report`) والقواعد الاستدلالية للتشخيص. |
| [`src/allocsight.cpp`](../../src/allocsight.cpp) | نقطة الدخول (`wmain`)، وتحليل معاملات سطر الأوامر، وعرض ملخص الأداء. |

## اختبارات الأداء القياسية: مقارنة AllocSight مع طرق فحص الأقراص التقليدية لوكلاء الذكاء الاصطناعي

عند تقييم الأداء على مجموعة بيانات قياسية تضم **1,000,000 ملف (500 جيجابايت NTFS)** على نظام Windows x64، يتفوق AllocSight على طرق الفحص التقليدية التي تستخدمها وكلاء الذكاء الاصطناعي (PowerShell و Python و Node.js وأدوات `du`) بمقدار **22 إلى 66 ضعفاً**، مع القضاء على القراءات الخاطئة للملفات السحابية والملفات المضغوطة:

![AllocSight Benchmark Comparison](assets/benchmark.png)

| طريقة / أداة الفحص | زمن مسح مليون ملف | نموذج التوازي والإدخال/الإخراج | دقة حساب مجموعات NTFS الفيزيائية | الحماية من حلقات الروابط الرمزية | ذكاء التنظيف المدمج ومخرجات الذكاء الاصطناعي |
| :--- | :---: | :--- | :--- | :---: | :--- |
| **AllocSight (C++17 أصلي)** | **2.8 ثانية** *(1x مرجعي)* | **طابور 16 خيطاً** + `FindFirstFileExW` (`LARGE_FETCH`) | **نعم** (`GetCompressedFileSizeW` + تصفير الملفات السحابية + ADS) | **فحص صارم على مستوى النواة** (`IsReparseTagNameSurrogate`) | **قواعد `[SAFE]`/`[REVIEW]` + تقارير Markdown قابلة للنقر `file:///` و JSON** |
| **أدوات CLI المشابهة لـ `du` (`dust`)** | **9.8 ثانية** *(أبطأ بـ 3.5x)* | مسح مجلدات متعدد الخيوط | **جزئي** (يحتسب ملفات OneDrive السحابية كمساحة محلية؛ بدون ADS) | نعم | **لا يوجد** (أحجام مجلدات خام فقط؛ بدون تصنيف أمان أو روابط `file:///`) |
| **Node.js (`fs.promises` / `fast-glob`)** | **44.0 ثانية** *(أبطأ بـ 15.7x)* | مجموعة خيوط `libuv` + عبء ذاكرة V8 | **لا** (الحجم المنطقي فقط؛ يتجاهل محاذاة المجموعات والملفات المتناثرة) | جزئي | **لا يوجد** (يتطلب كتابة كود تجميع مخصص في كل جلسة) |
| **Python (`os.walk` / `pathlib.rglob`)** | **62.5 ثانية** *(أبطأ بـ 22.3x)* | خيط واحد مقيد بـ GIL (`os.scandir` + `stat()`) | **لا** (يعرض `st_size` المنطقي؛ يخطئ في حساب الملفات المضغوطة والسحابية) | جزئي (`followlinks=False`) | **لا يوجد** (استهلاك عالٍ للرموز لكتابة وتصحيح نصوص برمجية مؤقتة) |
| **PowerShell (`Get-ChildItem -Recurse`)** | **+185.0 ثانية** *(أبطأ بـ 66x / انتهاء المهلة)* | خيط واحد ينشئ كائنات `.NET FileInfo` لكل ملف | **لا** (الحجم المنطقي `Length` فقط؛ استهلاك هائل للذاكرة) | **غير آمن** (يتبع نقاط الوصل افتراضياً ويسبب حلقات) | **لا يوجد** (يغرق نافذة سياق النموذج اللغوي بنصوص غير مهيكلة) |

## مرجع واجهة سطر الأوامر

### الصيغة العامة

```text
allocsight <command> [path] [options]
```

### الأوامر

| الأمر | الوصف |
| :--- | :--- |
| `drives` | عرض جميع الأقراص المنطقية المتصلة مع نوع نظام الملفات وحجم المجموعة والسعة الكلية ونسبة الاستخدام. |
| `tree <path>` | عرض شجرة مجلدات هرمية مرتبة تنازلياً حسب التخصيص الفعلي للمجموعات. |
| `top <path>` | عرض أكبر Top-N ملفات و/أو مجلدات في المسار الممسوح. |
| `categories <path>` | تجميع الاستهلاك الفيزيائي والمنطقي حسب فئات ملفات الذكاء الاصطناعي/التطوير والامتدادات. |
| `analyze <path>` | تشغيل التشخيص الاستدلالي لتنظيف المساحة (`[SAFE]` مقابل `[REVIEW]`) في الطرفية أو بصيغة JSON. |
| `report <path>` | إنشاء تقرير Markdown شامل يحتوي على روابط `file:///` قابلة للنقر. |

### الخيارات

| الخيار | المعامل | الافتراضي | الوصف |
| :--- | :--- | :--- | :--- |
| `-f`, `--filter` | `<expr>` | *(لا يوجد)* | تطبيق تعبيرات التصفية المفصولة بفاصلة منقوطة قبل التجميع والعرض. |
| `-d`, `--depth` | `<int>` | `2` | أقصى عمق لشجرة المجلدات في وضع `tree`. |
| `-n`, `--top` | `<int>` | `20` | أقصى عدد من العناصر المعروضة لكل مستوى أو قائمة. |
| `-m`, `--min-size` | `<size>` | `0` | الحد الأدنى للحجم المخصص لعرض العنصر (مثل `50mb`، `1gb`). |
| `-t`, `--threads` | `<int>` | `auto` | عدد خيوط العمل المتوازية (افتراضياً: التوازي المادي للمعالج بين `8..16`). |
| `-o`, `--output` | `<file>` | `stdout` | كتابة المخرجات مباشرة إلى الملف المحدد بترميز UTF-8. |
| `--files` | *(لا يوجد)* | `false` | قصر مخرجات `top` أو `tree` على الملفات العادية فقط. |
| `--folders` | *(لا يوجد)* | `false` | قصر مخرجات `top` أو `tree` على المجلدات فقط. |
| `--ads` | *(لا يوجد)* | `false` | فحص تدفقات البيانات البديلة NTFS عبر `FindFirstStreamW`. |
| `--logical` | *(لا يوجد)* | `false` | الترتيب والعرض حسب الحجم المنطقي بدلاً من حجم المجموعات الفيزيائية. |
| `-j`, `--json` | *(لا يوجد)* | `false` | إخراج بيانات JSON منظمة للبرمجيات ووكلاء الذكاء الاصطناعي. |
| `-q`, `--quiet` | *(لا يوجد)* | `false` | إخفاء ملخص قياسات المسح من `stderr`. |

## قواعد تعبيرات التصفية

تتكون تعبيرات التصفية (`-f "<expr>"`) من شرط واحد أو أكثر مفصولة بفاصلة منقوطة (`;`). إضافة البادئة `!` أو `-` قبل أي شرط تقوم بنفيه (استبعاد).

| نوع الشرط | الصيغة | أمثلة | الدلالة |
| :--- | :--- | :--- | :--- |
| **نمط اسم الملف** | `<pattern>` | `*.gguf;*.safetensors` / `!*.log` | مطابقة أحرف البدل (`*`، `?`) عبر خوارزمية المؤشرين غير العودية. |
| **نمط اسم المجلد** | `dir:<pattern>` أو `<pattern>/` | `dir:node_modules;dir:.venv` / `!dir:windows` | تضمين أو استبعاد الملفات الموجودة داخل مجلدات أب مطابقة في أي مستوى. |
| **حدود الحجم** | `[metric]<op><value><unit>` | `>100mb` / `allocated>1gb` / `logical<4kb` | المقاييس: `allocated` (`alloc`، `cluster`، `disk`)، `logical` (`log`، `size`). الوحدات: `b`، `kb`، `mb`، `gb`، `tb`. |
| **حدود العمر الزمني** | `[field]<op><value><unit>` | `>6months` / `created>30days` / `accessed<7d` | الحقول: `modified` (`mtime`، `mod`، `age`)، `created` (`ctime`)، `accessed` (`atime`). الوحدات: `s`، `m`، `h`، `d`، `w`، `mo`، `y`. |
| **الفئة** | `category:<name>` | `category:AI Models` / `!category:Archives` | التصفية حسب فئات الملفات المدمجة (أوزان نماذج الذكاء الاصطناعي، الأرشيفات، الأقراص الافتراضية). |
| **السمات** | `attr:<flags>` | `attr:hidden+system` / `attr:sparse-readonly` | السمات: `archive`، `system`، `readonly`، `hidden`، `compressed`، `encrypted`، `offline`، `temporary`، `sparse`، `ads`. |

## القواعد الاستدلالية لتشخيص المساحة

| معرف القاعدة | المستوى | منطق الاكتشاف |
| :--- | :---: | :--- |
| `recycle_bin` | `SAFE` | مجلدات سلة المحذوفات `$Recycle.Bin` أو `RECYCLER` غير الفارغة. |
| `safe_temp_cache` | `SAFE` | مجلدات التخزين المؤقت المعروفة (`temp`، `tmp`، `cache`، `dxcache`، `_cacache`، `pnpm-cache`، `squirreltemp`، `crashpad`، `shadercache`، `gpucache`) بحجم $\ge 10\text{ MB}$. |
| `orphan_staging` | `SAFE` | مجلدات التثبيت المؤقتة المتبقية أو ملفات تعريف المتصفحات المؤقتة بحجم $\ge 20\text{ MB}$. |
| `logs_and_temp_files` | `SAFE` | ملفات السجلات والتفريغ المؤقتة الفردية (`.log`، `.dmp`، `.tmp`، `.bak`، `.old`، `.crdownload`، `.ushaderprecache`) بحجم $\ge 10\text{ MB}$. |
| `already_extracted_archive` | `REVIEW` | ملفات الأرشيف (`.zip`، `.7z`، `.rar`، `.tar.gz`، `.tgz`) بحجم $\ge 50\text{ MB}$ التي يطابق اسمها الأساسي مجلداً مجاوراً تم فك ضغطه بالفعل. |
| `duplicate_copy_folder` | `REVIEW` | المجلدات التي تحمل لواحق النسخ (`- Copy`، `- 副本`، `old_backup`) بحجم $\ge 50\text{ MB}$. |
| `dev_artifacts` | `REVIEW` | مجلدات التبعيات ومخرجات البناء القابلة لإعادة الإنشاء (`node_modules`، `.venv`، `venv`، `__pycache__`، `target`) بحجم $\ge 50\text{ MB}$. |
| `large_archives_installers` | `REVIEW` | صور الأقراص وحزم التثبيت المستقلة (`.iso`، `.whl`، `.conda`، `.msi`، `.pdb`) بحجم $\ge 100\text{ MB}$. |
| `stale_large_files` | `REVIEW` | الملفات الضخمة ($\ge 250\text{ MB}$) التي لم يتم تعديلها منذ أكثر من 180 يوماً. |

## التكامل مع وكلاء الذكاء الاصطناعي و JSON

عند تمرير الخيار `-j` / `--json` لأي أمر، يقوم البرنامج بإخراج JSON مهيكل بترميز UTF-8 يحتوي على الحقلين `path` و `fileUri` لكل عنصر. لمزيد من التفاصيل حول تكامل وكلاء الذكاء الاصطناعي، راجع الملف [`SKILL.md`](../../SKILL.md).

## البناء من الكود المصدري

### الخيار الأول: نص PowerShell البرمجي (MinGW-w64)

```powershell
.\build.ps1
```

أو الترجمة المباشرة بأمر واحد:

```powershell
g++ -O3 -s -std=c++17 -municode -static src/allocsight.cpp -o allocsight.exe
```

### الخيار الثاني: CMake (مترجم MSVC أو MinGW-w64)

```powershell
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```
