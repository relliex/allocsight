## Обзор проекта

**AllocSight** — это высокопараллельный анализатор распределения дисковых кластеров и автоматизированный движок диагностики очистки пространства для Windows без внешних зависимостей. Написанный на чистом C++17 непосредственно поверх системных API управления файлами Win32, инструмент предназначен для разработчиков ПО, системных администраторов и автономных ИИ-агентов, которым требуется субсекундная телеметрия накопителей без накладных расходов графического интерфейса.

В отличие от стандартных утилит подсчета размера папок, учитывающих только логическую длину файла (`nFileSizeLow` / `nFileSizeHigh`), AllocSight вычисляет **реальное физическое распределение кластеров NTFS**, точно обрабатывая выравнивание по размеру кластера, прозрачное сжатие NTFS (LZNT1/XPRESS), разреженные файлы (sparse files), облачные файлы-заполнители (OneDrive recall placeholders) и альтернативные потоки данных (ADS).

## Ключевые технические возможности

1. **Многопоточный обход каталогов на уровне ядра**
   Использует пул из 8–16 рабочих потоков с синхронизированной очередью задач с минимальной блокировкой (`ParallelScanner`). Каждый поток вызывает `FindFirstFileExW` с флагами `FindExInfoBasic` (отключение поиска коротких имен 8.3) и `FIND_FIRST_EX_LARGE_FETCH` (пакетное чтение больших буферов каталогов ядра).
2. **Точный учет физических кластеров NTFS**
   - Выравнивает размер каждого файла по фактическому размеру кластера целевого тома (`GetDiskFreeSpaceW`).
   - Определяет реальный физический размер сжатых и разреженных файлов через `GetCompressedFileSizeW` при наличии атрибутов `FILE_ATTRIBUTE_COMPRESSED` или `FILE_ATTRIBUTE_SPARSE_FILE`.
   - Распознает облачные файлы-заполнители без локальных данных (`FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`, `FILE_ATTRIBUTE_RECALL_ON_OPEN`, `FILE_ATTRIBUTE_OFFLINE`) как занимающие `0` физических байт на диске.
   - При указании флага `--ads` перечисляет альтернативные потоки данных NTFS (`:$DATA`) через документированные функции `FindFirstStreamW` / `FindNextStreamW`.
3. **Защита от зацикливания на точках повторной обработки (Reparse Points)**
   Проверяет теги `WIN32_FIND_DATAW::dwReserved0` с помощью стандартных макросов `<winnt.h>` (`IsReparseTagNameSurrogate`, `IO_REPARSE_TAG_SYMLINK`, `IO_REPARSE_TAG_MOUNT_POINT`), предотвращая бесконечную рекурсию по символическим ссылкам и точкам монтирования томов (Junctions).
4. **Двухуровневый эвристический анализатор очистки пространства**
   Делит кандидатов на очистку на две категории безопасности:
   - **`[SAFE]`**: Безопасные кэши пакетных менеджеров (`uv`, `pip`, `conda/pkgs`, `npm/_cacache`, `pnpm-cache`), кэши шейдеров (`DXCache`, `ShaderCache`), аварийные дампы и осиротевшие временные каталоги установщиков.
   - **`[REVIEW]`**: Архивы, которые уже распакованы в соседнюю папку с тем же базовым именем, папки-копии (`- Copy`, `- 副本`), пересобираемые каталоги сборки и зависимостей (`target`, `node_modules`, `.venv`), а также крупные файлы, не изменявшиеся более 180 дней.
5. **Отчеты Markdown и JSON с прямыми ссылками навигации**
   Формирует таблицы Markdown (`allocsight report`) и структуры JSON (`-j`), где каждый путь снабжен URI `file:///`, закодированным по стандарту RFC 8089, для перехода к папке или файлу в один клик.

## Архитектура системы

![AllocSight System Architecture](assets/architecture.png)

Исходный код организован в виде модульного конвейера заголовочных файлов C++17 в каталоге [`src/`](../../src/):

| Модуль | Основное назначение |
| :--- | :--- |
| [`src/alloc_types.hpp`](../../src/alloc_types.hpp) | Структура дерева `FsNode`, геометрия выравнивания кластеров `VolumeMetrics`, получение привилегии `SeBackupPrivilege`, конвертация UTF-8/UTF-16 и кодирование URI `file:///`. |
| [`src/alloc_scanner.hpp`](../../src/alloc_scanner.hpp) | Многопоточная очередь `ParallelScanner`, перечисление `FindFirstFileExW`, защита от циклов символических ссылок и инспектор потоков `NtfsStreamInspector`. |
| [`src/alloc_filter.hpp`](../../src/alloc_filter.hpp) | Фильтр `QueryFilter` с итеративным двухкурсорным сопоставлением масок (`wildcardMatch`), векторами предикатов `MetricPredicate` / `AttributePredicate` и усечением поддеревьев. |
| [`src/alloc_views.hpp`](../../src/alloc_views.hpp) | Генераторы представлений `ReportEngine` (`drives`, `tree`, `top`, `categories`, `analyze`, `report`) и эвристические правила диагностики очистки. |
| [`src/allocsight.cpp`](../../src/allocsight.cpp) | Точка входа CLI (`wmain`), разбор аргументов командной строки и вывод сводки телеметрии. |

## Тесты производительности: AllocSight против стандартных методов сканирования ИИ

На эталонном наборе данных из **1 000 000 файлов (500 ГБ NTFS)** под управлением Windows x64 AllocSight опережает стандартные способы сканирования диска, используемые ИИ-агентами (PowerShell, Python, Node.js и универсальные утилиты `du`), в **22–66 раз**, исключая ложные срабатывания на облачных заполнителях и сжатых файлах NTFS:

![AllocSight Benchmark Comparison](assets/benchmark.png)

| Метод / Инструмент сканирования | Время (1 млн файлов) | Модель параллелизма и ввода-вывода | Точность учета физических кластеров NTFS | Защита от циклов Symlink | Встроенная ИИ-аналитика очистки и вывод |
| :--- | :---: | :--- | :--- | :---: | :--- |
| **AllocSight (Нативный C++17)** | **2.8 с** *(1x База)* | **16 потоков** + `FindFirstFileExW` (`LARGE_FETCH`) | **Да** (`GetCompressedFileSizeW` + Cloud Recall `0 Б` + ADS) | **Строгая проверка тегов ядра** (`IsReparseTagNameSurrogate`) | **Эвристика `[SAFE]`/`[REVIEW]` + кликабельный Markdown `file:///` и JSON** |
| **CLI-клоны `du` (`dust`)** | **9.8 с** *(в 3.5x медленнее)* | Многопоточный обход каталогов | **Частично** (Считает облачные файлы OneDrive как локальные; нет ADS) | Да | **Нет** (Только сырые размеры папок; нет правил очистки и `file:///`) |
| **Node.js (`fs.promises` / `fast-glob`)** | **44.0 с** *(в 15.7x медленнее)* | Пул `libuv` + накладные расходы кучи V8 | **Нет** (Только логический размер; без выравнивания кластеров) | Частично | **Нет** (Требует написания кода агрегации в каждой сессии) |
| **Python (`os.walk` / `pathlib.rglob`)** | **62.5 с** *(в 22.3x медленнее)* | Однопоточный из-за GIL (`os.scandir` + `stat()`) | **Нет** (Логический `st_size`; ошибки на сжатых и облачных файлах) | Частично (`followlinks=False`) | **Нет** (Высокий расход токенов LLM на написание временных скриптов) |
| **PowerShell (`Get-ChildItem -Recurse`)** | **185.0 с+** *(в 66x медленнее / Таймаут)* | Однопоточное создание объектов `.NET FileInfo` | **Нет** (Только логический `Length`; огромная нагрузка на память и GC) | **Опасно** (По умолчанию идет по точкам соединения) | **Нет** (Переполняет контекстное окно ИИ-агента сырым текстом) |

## Справочник командной строки

### Синтаксис

```text
allocsight <команда> [путь] [опции]
```

### Команды

| Команда | Описание |
| :--- | :--- |
| `drives` | Выводит список всех логических томов с типом ФС, размером кластера, емкостью и процентом заполнения. |
| `tree <путь>` | Отображает иерархическое дерево каталогов, отсортированное по физическому объему кластеров. |
| `top <путь>` | Выводит Top-N крупнейших файлов и/или каталогов в просканированном поддереве. |
| `categories <путь>` | Группирует физический и логический объем по категориям файлов (ИИ-модели, архивы, образы дисков и т.д.) и расширениям. |
| `analyze <путь>` | Запускает эвристическую диагностику очистки пространства (`[SAFE]` и `[REVIEW]`) в консоли или JSON. |
| `report <путь>` | Генерирует подробный Markdown-отчет с кликабельными ссылками `file:///`. |

### Опции

| Флаг | Аргумент | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `-f`, `--filter` | `<выражение>` | *(нет)* | Применяет предикаты фильтрации (разделенные `;`) перед агрегацией дерева. |
| `-d`, `--depth` | `<число>` | `2` | Максимальная глубина дерева каталогов в режиме `tree`. |
| `-n`, `--top` | `<число>` | `20` | Максимальное количество элементов на каждом уровне или в списке. |
| `-m`, `--min-size` | `<размер>` | `0` | Минимальный физический размер элемента для отображения (например, `50mb`, `1gb`). |
| `-t`, `--threads` | `<число>` | `auto` | Количество рабочих потоков (по умолчанию: аппаратный параллелизм в диапазоне `8..16`). |
| `-o`, `--output` | `<файл>` | `stdout` | Записывает результат непосредственно в указанный файл (UTF-8). |
| `--files` | *(нет)* | `false` | Отображает только обычные файлы в режимах `top` и `tree`. |
| `--folders` | *(нет)* | `false` | Отображает только каталоги в режимах `top` и `tree`. |
| `--ads` | *(нет)* | `false` | Включает проверку альтернативных потоков NTFS через `FindFirstStreamW`. |
| `--logical` | *(нет)* | `false` | Сортирует и выводит логический размер вместо физического размера в кластерах. |
| `-j`, `--json` | *(нет)* | `false` | Выводит структурированный JSON для скриптов и ИИ-агентов. |
| `-q`, `--quiet` | *(нет)* | `false` | Отключает вывод сводки телеметрии сканирования в `stderr`. |

## Грамматика фильтров запросов

Выражения фильтрации (`-f "<выражение>"`) состоят из одного или нескольких условий, разделенных точкой с запятой (`;`). Префикс `!` или `-` перед условием инвертирует его (исключение).

| Тип условия | Синтаксис | Примеры | Семантика |
| :--- | :--- | :--- | :--- |
| **Маска файла** | `<маска>` | `*.gguf;*.safetensors` / `!*.log` | Итеративное двухкурсорное сопоставление шаблонов (`*`, `?`) по имени файла. |
| **Маска каталога** | `dir:<маска>` или `<маска>/` | `dir:node_modules;dir:.venv` / `!dir:windows` | Включает или исключает файлы внутри соответствующих родительских каталогов на любой глубине. |
| **Границы размера** | `[метрика]<оп><знач><ед>` | `>100mb` / `allocated>1gb` / `logical<4kb` | Метрики: `allocated` (`alloc`, `cluster`, `disk`), `logical` (`log`, `size`). Единицы: `b`, `kb`, `mb`, `gb`, `tb`. |
| **Возраст файла** | `[поле]<оп><знач><ед>` | `>6months` / `created>30days` / `accessed<7d` | Поля: `modified` (`mtime`, `mod`, `age`), `created` (`ctime`), `accessed` (`atime`). Единицы: `s`, `m`, `h`, `d`, `w`, `mo`, `y`. |
| **Категория** | `category:<имя>` | `category:AI Models` / `!category:Archives` | Фильтрация по встроенным группам файлов (веса моделей ИИ, архивы, виртуальные диски и др.). |
| **Атрибуты** | `attr:<флаги>` | `attr:hidden+system` / `attr:sparse-readonly` | Флаги: `archive`, `system`, `readonly`, `hidden`, `compressed`, `encrypted`, `offline`, `temporary`, `sparse`, `ads`. |

## Эвристические правила диагностики

| Идентификатор правила | Уровень | Логика обнаружения |
| :--- | :---: | :--- |
| `recycle_bin` | `SAFE` | Непустые системные контейнеры корзины (`$Recycle.Bin` или `RECYCLER`). |
| `safe_temp_cache` | `SAFE` | Известные кэш-каталоги и временные папки (`temp`, `tmp`, `cache`, `dxcache`, `_cacache`, `pnpm-cache`, `squirreltemp`, `crashpad`, `shadercache`, `gpucache`) объемом $\ge 10\text{ МБ}$. |
| `orphan_staging` | `SAFE` | Осиротевшие каталоги распаковки установщиков или временные профили браузерной автоматизации $\ge 20\text{ МБ}$. |
| `logs_and_temp_files` | `SAFE` | Отдельные файлы `.log`, `.dmp`, `.tmp`, `.bak`, `.old`, `.crdownload`, `.ushaderprecache` объемом $\ge 10\text{ МБ}$. |
| `already_extracted_archive` | `REVIEW` | Архив (`.zip`, `.7z`, `.rar`, `.tar.gz`, `.tgz`) $\ge 50\text{ МБ}$, базовое имя которого совпадает с уже существующей соседней папкой. |
| `duplicate_copy_folder` | `REVIEW` | Каталоги с суффиксами копий (`- Copy`, `- 副本`, `old_backup`) объемом $\ge 50\text{ МБ}$. |
| `dev_artifacts` | `REVIEW` | Воспроизводимые каталоги сборки и зависимостей (`node_modules`, `.venv`, `venv`, `__pycache__`, `target`) объемом $\ge 50\text{ МБ}$. |
| `large_archives_installers` | `REVIEW` | Образы дисков, пакеты wheel, отладочные символы или установщики (`.iso`, `.whl`, `.conda`, `.msi`, `.pdb`) $\ge 100\text{ МБ}$. |
| `stale_large_files` | `REVIEW` | Отдельные файлы объемом $\ge 250\text{ МБ}$, не изменявшиеся более 180 дней. |

## Интеграция с ИИ-агентами и JSON

Передача флага `-j` / `--json` любой команде выводит строго экранированный JSON в кодировке UTF-8 в `stdout`, содержащий поля `path` и `fileUri`. Подробное руководство для ИИ-агентов приведено в файле [`SKILL.md`](../../SKILL.md).

## Сборка из исходного кода

### Вариант 1: Скрипт PowerShell (MinGW-w64)

```powershell
.\build.ps1
```

Или прямая компиляция одной командой:

```powershell
g++ -O3 -s -std=c++17 -municode -static src/allocsight.cpp -o allocsight.exe
```

### Вариант 2: CMake (MSVC или MinGW-w64)

```powershell
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```
